# A02: Integrity Inspection and Startup Protection

日期：2026-10-08（Asia/Hong_Kong）。基線：`c5b7320`；工作分支：`codex/supplemental-development`。

## 範圍與發現

本批補齊隔離 V2 的完整性報告與副本修復預覽，並修正現行 V1 啟動順序中的資料保留風險。沒有啟用 V2 遷移、沒有操作使用者的實際詞庫、沒有執行 live AI 請求或 app 分發工作。README、產品截圖和全倉敏感資訊審核仍留在 C06。

檢查發現：原 `WordNoteApp.init` 在 `startAutomaticBackups` 前呼叫 `repairDanglingReferences`，會直接刪孤立 Candidate/ReviewEvent 並清外鍵。資料損壞或外鍵缺失不代表這些內容已無價值；自動先刪後備份可能丟失可恢復資料。本次將正常和 QA 啟動改為 `validateBeforeOpening` 只讀檢查。有問題則保留原庫並使用既有存儲錯誤頁，不允許在緊急記憶體容器中建立新詞。

取捨：正常庫保持原流程；斷鏈舊庫不再靠自動清理進入主頁，需要先處理存儲問題。這降低問題庫的即時可用性，但避免未獲確認的內容刪除。已選定 generation 後的錯誤頁會指向實際 store，而非始終顯示根目錄舊文件。

## V2 實作

1. 檢查全部 8 實體及 4 組元資料：ID、業務唯一鍵、外鍵、來源 capture/入口/詞條匹配、候選狀態，以及完整快照字段校驗。
2. 問題報告只有實體 ID、相關 ID、字段和分類，不包含詞義、筆記或原文。歷史非英文主體、unresolvedLegacy 和重複詞頭保留警告，不假裝已修正。
3. 只允許為缺失的三類可選外鍵準備解除方案：Term.sourceRecordID、Occurrence.sourceRecordID、LookupEvent.occurrenceID。行數、實體 ID、文本、課程、歷史事件保持不變；受影響 Term 的 revision 一次加一。
4. 缺課程、缺詞、孤立候選/事件、重複鍵、缺元資料、現存但指錯的來源和候選狀態衝突均阻止自動修復；不猜替代目標，不把「找不到詞」標成已明確刪除。
5. 先在值副本上模擬允許的解除，再完整 validate，避免 missingReference 掩蓋壞計數、日期、enum 或 generation。任何剩餘阻塞項使整個修復預覽失敗，不返回半完成副本。
6. RepairPlan 保存來源值；套用到 staged store 前必須重新讀取並比對全部值及非機密偏好。預覽後的內容改動即使未正確增加 revision，也會被拒絕。重跑已修復資料是無修改結果。
7. 容器入口拒絕 V1 和未提交的模型編輯，不替表單保存或 rollback；檢查/預覽沒有寫入副作用，恢復屏障期間仍能只讀檢查。

正常 snapshot capture/codec 繼續拒絕非法關係。僅內部 integrity 讀取方法可以取得尚未通過校驗的 DTO，用於報告；未提供繞過驗證的導入或在原庫直接套用修復的方法。修復副本必須寫入空 V2 目標庫，原庫保留。正式 UI、保護/確認和共用 staged 日誌接入仍待後續。

| 類別 | 證據 |
|---|---|
| V1 啟動 | 完整正常庫逐值不變；五類斷鏈帶 ID 報告；拒絕後沒有刪候選/事件或清外鍵；臨時 SQLite 重開仍有原記錄 |
| 跨版本/草稿 | V1 service 拒絕 V2 context；V2 service 拒絕 V1；兩者遇未保存編輯不提交、不丟棄 |
| V2 修復 | 三種可選外鍵解除，完整快照逐值核對；同詞多個修復只增一次 revision；再次修復無改變 |
| V2 阻塞 | 每類必需外鍵、八實體/四元資料重複 ID、四類業務鍵、缺/多元資料、候選狀態、跨 capture 或詞條來源均不自動清理 |
| 隱藏錯誤 | 可修復引用與非法日期/計數/enum/generation 同時存在時仍拒絕，無半修復資料 |
| 預覽一致性 | 改內容或偏好即過期，fetch 順序不影響報告/結果，revision 上限和非法時鐘拒絕 |
| 隔離持久化 | 問題原 SQLite 保持原 DTO；修復副本寫入另一文件並重開與預期全部字段一致；非空原庫拒絕 populate |
| 資料最小化 | 編碼問題清單僅有 ID/分類，不含測試的詞義/私人筆記標記；這不是全倉敏感資訊掃描 |
